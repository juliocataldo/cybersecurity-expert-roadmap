Agents - Windows

Type: Cyber
Skills: WindowsMicro-segmentation

Agents can be install in these OS

  • Windows
  • Linux
  • MAC
  • Unix

==The policy is applied through the driver (windows), kernel(linux), native pf fw (MacOS).

Agents - Modules/Bundles

  • Reveal Module - Enables process-level (L7) visibility and file reputation - Responsible for reporting the visibility data collected by the Agents and also the enforcement log
  • Enforcement Modules - Blocks traffic based on network-level process-level and collects responses for DNS requests
  • Deception Module - Detects failed/blocked connection attempts and redirects those to the Deception Server for further investigation
  • Detection Module - Responsible for insight capabilites

Additional Internal module

  • Controller Module - Communication channel between the Agent and the Aggregator for monitoring and control of the Agent

|Agent Side| Aggregator Side|
|---|---|
|Reveal module| gc-mitigation |
|Enforcement module| gc-enforcement|
|Deception module| gc-datapath|
|Detection module| gc-detection-agents-server|
|Controller| gc-controller-server|

Agent Resilience

  • In case connectivity between the Agent and the Agg is lost, the agent will continue its operation
  • Last updated policy revision will be enforced
  • the policy is stored in a file that requires root privileges to access it
  • New traffic flow data will be cached in the memory and reported once the connectivity to the aggregator is renewed.
  • the flow data is stored in memory, until a configurable limit of numbers of network is reached
  • When agent process are killed, a wathcdog service will restart them.

Windows

Storage, CPU and Memory Utilization

There are 3 pre-configured resource usage limitation profiles:

  • low
  • medium (default)
  • high

All module share the same limitation values

  • Soft limits - restrict usage for the current process, but may be exceeded in situations when the resource is not requested by concurrent processes. The soft limit default value is 2% and can be changed per Agent
  • Hard Limits - restrict resource usage to an absolute ceiling cannot be exceeded. The hard limit default value is 5% and can be changed per Agent

==In most windows environment it is found to utilize less than 1% of CPU. CPU Limitations are enforced starting 2k12, using Windows Job Objects mechanism.

==In most windows environment it is found to utilize less than 50MB of RAM. Memory limit are enforced starting 2003, using Windows Job Objects mechanism.

==All agent sub components initiation is done using a service named GC-AGENTS-SERVICE - In case of failure, the process is restarted after a 20 second wait time

Online vs offline

Online: The installation flow pulls the Agent package from the Aggregator, then the flow installs and configures the Agent. The installation instructions for this option per OS are included in Centra. Online installation allos installing the latest version

Offline: A package file is placed in the customers repo and copied and installed on a target server by customer's scripts. Offline installation allows control of the deployed binaries. It can be also used in case the Aggregator cannot yet be reached but the project already wants to deploy an Agent.

Agent installation profile

  • The default profile is the base profile
  • any agent that is installed without an installation profile is associated with the default
  • installation profile are relevant for install time only
  • Agent configuration can always be changed after install
  • To change an Agent's attributes, you need to override its configuration
  • To change an Agent's installation profile, you will need to uninstall the Agent and reinstall it.

==Akamai suggest to never change the default installation profile and never edit

  • We can specify the installation profile using the installer CLI interface:

`windows_installer.exe /q /a <AGGR_IP/FQDN> /p <passowrd> /installation-profile <installation_profile_name>

Uninstalling

From Windows: Control Panel --> Uninstall (no downtime)

Upgrade

The usual upgrade procedure is to reinstall the Agent. An agent can also be upgraded from Centra.

Remote agent upgrade (RAU)

Administrators can upgrade agents directly from Centra-s Agents screen. Simply selects the Agent(s) to be upgraded and clicks the remote agents upgrade button.

  • You can select 1000 agents at a time, the batch size is 100 - average 30 seconds per agent
  • Remote agent upgrade feature is supported to Linux and Windows

**If agent admin lock enabled, disable it first, before you begin the upgrade.

Windows Agent Adm Lock

  • Agent lock prevents Agent tampering by an unprivileged server adm which may causa the agent to be suspended or disabled.

To prevent disabling the Agent, the following is prevented:

  • Uninstalling the agent through Add/Remove programs.
  • Stopping/Restarting/Disabling the Agent service
  • Killing the agent process in the task manager.

==On other Operations System (OS):

  • The adm lock protects only the gc -agent binary, which controls the Agent status.
  • The adm lock does not protect Agent from being uninstalled or stopped by using standard OS methods.

BY DEFAULT, THE AGENT TAMPER PREVENTION LOCK IS DISABLED FOR EXISTING AGETNS OR NEWLY INSTALLED AGENTS.

  • In Centra ADM installs the agent with the locked enabled using profile configuration
  • Centra Adm uses Administration lock option on the agents screen to change an Agent's state to Locked.
