We created a variable called X and in that we stored a value called for 4.

==Important: With you use single quotes, the shell understands it is string and the output is exactly what is inside the simple quotes, but now, if you use double quotes the shell understands it is variable and the output is what is inside that variable (stored in variable)

In Linux Shell Scripting, there are two types of variable:

  1. System variables:
  2. created and maintained by Operating System itself
  3. This type of variable are defined in CAPITAL LETTERS
  4. We can see them by using set command
  5. Example: HOME, USER ....
  6. User Defined Variables
  7. Created an maintained by the yuser
  8. This type of variable are defined in lower letters
  9. But we can algo take combination of upper and lower case letters.

Rules to Define User Defined Variables

  • Variables name should contain only a-z or A-Z, 0-9 and _ characters.
  • Variable Name length should be less than or equal to 20 characters.
  • Variable Names are case sensitive
  • Do not provide space on either sides of equal symbol
  • x=4 --> Valid
  • x = 4 --> Invalid
  • No need to declare variable type, automatically it will take care while executing command or scripts
  • We can store the output of a command into a variable as follows:
  • $(command)
  • $command

Examples of cat <<EOF syntax usage in Bash:

The cat <<EOF syntax is very useful when working with multi-line text in Bash, eg. when assigning multi-line string to a shell variable, file or a pipe.

1. Assign multi-line string to a shell variable

$ sql=$(cat <<EOF
SELECT foo, bar FROM db
WHERE foo='baz'
EOF
)

The $sql variable now holds the new-line characters too. You can verify with echo -e "$sql".

2. Pass multi-line string to a file in Bash

$ cat <<EOF > print.sh
#!/bin/bash
echo \$PWD
echo $PWD
EOF

The print.sh file now contains:

#!/bin/bash
echo $PWD
echo /home/user

3. Pass multi-line string to a pipe in Bash

$ cat <<EOF | grep 'b' | tee b.txt
foo
bar
baz
EOF

The b.txt file contains bar and baz lines.

Standard streams

 standard streams are interconnected input and output communication channels between a computer program and its environment when it begins execution. The three input/output (I/O) connections are called standard input (stdin), standard output (stdout) and standard error (stderr).

The standard streams for input, output, and error:

To redirect stdout to file.txt:

echo test > file.txt

This is equivalent to:

echo test 1> file.txt

To redirect stderr to file.txt:

echo test 2> file.txt

To redirect stdout to stderr:

echo test 1>&2   # equivalently, echo test >&2

To redirect stderr to stdout:

echo test 2>&1

Thus, in 2>&1:

  • 2> redirects stderr to an (unspecified) file.
  • &1 redirects stderr to stdout.

redirects standard output (stdout) to /dev/null, which discards it.
