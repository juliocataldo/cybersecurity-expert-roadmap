Segmentation Rules

1. Override Rules

Override Allow/Alert/block rules take precedence over any other

2. Allow Rules

These rules are used to build an allow list of allow flows. Traffic matched by these rules will be explicit allowed.
Allow rules take precedence over Alert and Block Rules.

3. Alert Rules

These rules are used to build a monitoring segmentation policy. Traffic matched by these rules will be allowed but will trigger a 'Policy Violation' incident.

4. Block Rules

These rules are used to build an enforcement polocy. Traffic matched by these rules will be blocked, if action is 'block and alert' a 'policy Violation' incident will also be triggered.

Source and Destination

  1. Label Group
  2. Labels

  4. Process
  5. Subnets

**FQDN Rules:

  • Allow connections to the internet from specific server groups to FQDN instead of long, dynamic IP lists.
  • Allow connections to internal FQDN addresses that are not covered by agents
  • Block by FQDN is not currently supported - Use DNS Security feature

Rule Structure: Labels AND/OR Combinations

OR: In different lines
AND: In the same line

Rule Structure: User Groups

User Groups - Can create allow rules whose SOURCE Field is restricted to specific User groups are derived from groups in the AD.
**Source must be a Windows server with an Agent installed. - To active this feature, you must first configure ORCHESTRATION to the AD and to create User Group. On the OS level, the Agent queries the OS and matches if the origin user is part of the AD groups SID.

Process/Service: Fullpath /Allpath

Allpath --> The policy will apply the process/service regardless of the directory from which the process/service is run
Fullpath --> The policy will apply to the process/service only if it is run from the specified directory

New process (not recognized by Reveal) - The policy will apply to the new process/service. To select a new process/service, click Manually add and type the name of the process.

Rule Structure: Ports / Protocols

You can narrow the scope of a rule by specifying the protocol and ports.
TCP/UDP - specify the ports, separated by commas.
ICMP - Selecting the ICMP option to specify or not selecting anything in this field will apply the rule to all ICMP traffic

Rule Structure: Ruleset

For ease of exploration and local association of a rule with its purpose.

Network Logs Action Filter

Will be blocked - Management contain Block rules which are matched on an agent with enforcement module set to Monitor mode are reported with 'Will be blocked' action.

Could not Block - states management policy verdict is Block, while the Agent's verdict is Allow, and they allowed the flow. Check the Management and Agent health, policy revision, and log to get to the root cause of the mismatch

Rule Hit Counter

Displays the number of times a rule is matched to an observed connection, enabling you to keep track of the number of times a rule is used.

  • hit Count allows us to:
  • Identify unused Allow rules
  • Identify triggered Alert/Block rules
  • View metrics of N-S / E-W connections rates within environments, applications etc
  • Rule Hit Count refresh rate is up to 5 minutes

DNS Security

  • DNS security feature filters access to malicious domains including malware, phishing and CnC domains
  • Administrators can add their own Blocklists using Guardicore DNS Security scree
  • The feature supports multiple lists - total up to 1M domains
  • On the Agent side, the DNS Security feature is enabled by default
