Nmap

#offsec #tools

Type: Linux Cyber
Skills: Code Hacking

Nmap is a free port scanning software developed by Gordon Lyon, self-proclaimed hacker "Fyodor". It is widely used to assess computer security, and to discover services or servers on a computer network. It can e used in Linux.

Commands

  1. Simple Scan: This command performs a basic scan on the target host or network, identifying open ports and services.

==nmap <target>

  1. Scan a Range of Hosts: You can specify a range of IP addresses to scan multiple hosts simultaneously.

==nmap <startIP>-<endIP>

  1. Scan a Subnet: This command allows you to scan an entire subnet by specifying the network address and subnet mask.

===nmap <network>/<subnet>

  1. Operating System Detection: Nmap can attempt to determine the operating system running on the target host.

==nmap -O <target>

  1. Service Version Detection: This command attempts to determine the version of services running on open ports.

==nmap -sV <target>

  1. Aggressive Scan: The aggressive scan option enables a broader range of techniques to gather more information.

==nmap -A <target>

  1. Scan for UDP Services: By default, Nmap scans for TCP services, but this command allows you to scan for UDP services.

==nmap -sU <target>

  1. Scan Multiple Ports: You can specify multiple ports or port ranges to scan.

==`nmap -p <port1,port2,port3> <target>
`nmap -p 1-1000 <target>
`nmap --top-ports <number> <target>

8.1. Scan all Ports: You can scan all ports

==nmap -p- <target>

  1. Scan using a specific script: Nmap has a wide range of scripts for various scanning and enumeration tasks. This command runs a specific script.

==nmap --script=<scriptname> <target>

  1. Save Output to a File: You can save the scan results to a file for further analysis.

==nmap -oN <outputfile> <target>

  1. scan TCP SYN

O scan SYN é a opção de scan padrão e mais popular por boas razões. Pode ser executada rapidamente, escaneando milhares de portas por segundo em uma rede rápida, não bloqueada por firewalls intrusivos. O scan SYN é relativamente não-obstrusivo e camuflado, uma vez que ele nunca completa uma conexão TCP. Ele também trabalha contra qualquer pilha TCP padronizada ao invés de depender de idiossincrasias de plataformas específicas como os scans Fin/Null/Xmas, Maimon e Idle fazem. Ele também permite uma diferenciação limpa e confiável entre os estados aberto (open), fechado (closed), e filtrado (filtered).

==`nmap -sS -p 80,443 189.39.64.216

  1. It tells nmap not to send ICMP echo requests

This option disables host discovery and assumes that all specified targets are online.

==`nmap -Pn -p 80,443 189.39.64.216

ENGANANDO O PENTEST NO REASON (CONFIGURAÇÃO DO FIREWALL)
==nmap -sS -p 80 -Pn 172.16.1.5 --reason

SCAN TECHNIQUES:
  -sS/sT/sA/sW/sM: TCP SYN/Connect()/ACK/Window/Maimon scans
  -sU: UDP Scan
  -sN/sF/sX: TCP Null, FIN, and Xmas scans
  --scanflags <flags>: Customize TCP scan flags
  -sI <zombie host[:probeport]>: Idle scan
  -sY/sZ: SCTP INIT/COOKIE-ECHO scans
  -sO: IP protocol scan
  -b <FTP relay host>: FTP bounce scan

Comments

So, you are dropped on a /16 subnet – what do you do?

Gather a list of live hosts! A /16 subnet has over 65,000 hosts. Not all of them will be alive/active (unless you are testing Mark Zuckerberg’s home network). You need to run a scan that will quickly determine if a host is up or not before checking any ports – this will save you loads of time. Here’s how you do it:

==`nmap -sS <subnet> --disable-arp-ping -p 22,80,135,445 -n --max-retries=0 -T4 -oA <filename>

Why is this faster? Here’s what the flags mean:

-sS -> TCP SYN scan, fast and stealthy since it never fully completes TCP scans

--disable-arp-ping -> Tells Nmap to skip the preliminary ARP sweep, moving straight to higher-level discovery (ICMP echo requests). This helps make sure we don’t accidentally skip live hosts because some hosts will drop ARP requests or responses that exceed a certain threshold, making the host appear down when it is really up. Make sure you are running as root for this to work

-p -> Checks for common ports 22 and 80 for Linux, 135 and 445 for Windows

-n -> Never do reverse DNS resolution, since it will slow us down

--max-retries=0 -> Don’t do any retransmissions upon the host appearing down

-T4 -> Tells Nmap to speed the scan up by assuming we’re on a fast and reliable network. You can even go to T5, but that is called ‘insane’ mode for a reason

-oA -> Output in all available file formats

When this scan is finished, you can do something like the following to get your list of live hosts:

egrep Up <filename>[.]gnmap | cut -d ' ' -f 2 >> live-hosts.txt

And there you go! You have your list of live hosts on the network and can begin port scanning them. This will save you lots of time. It is worth mentioning that it is a good idea to combine this scan with querying DNS, just in case some hosts block ICMP altogether. You can gather DNS info with the below commands:

dig -x <IP> @<DNS_IP>
dig ANY <DOMAIN> @<DNS_IP>
