Protocolos Ethernet

#network #security

Skills: Network Cyber

Protocolo Ethernet

Estrutura do protocolo ethernet

Mac Destino: Contém o endereço físico da paca de rede destino
Mac Origem: Contém o endereço físico da placa de rede de origem
Tipo: Código de identifica o tipo de protocol (0900 = IP / 0806 = ARP)
Payload: Contém os dados a serem transportados, o tamanho máximo do payload é de 1500 bytes.

Broadcast é o endereço que indica todo segmento ethernet (ff:ff:ff:ff:ff:ff)

Protocolo ARP

O ARP tem a habilidade de descobrir qual endereço MAC está associado a um determinado endereço IP. Para fazer isso o ARP utiliza os famosos ARP Request e ARP Reply

ARP Request pergunta quem tem determinado IP e qual o seu endereço MAC. ARP Reply é a resposta enviada pelo host que tem o IP requisitado, ao responder ao ARP Request o host envia seu endereço MAC.

O host que recebe a resposta armazena o IP e MAC por um tempo.

Estrutura Protocolo ARP

A estrutura do ARP tem 4 bytes de largura MAC = 6 bytes IP = 4 bytes
Como o MAC tem tamanho 6 e a estrutura ARP só cabe 4 por linha, ela faz a adaptação

Protocolo IP

Responsável por realizar a entrega de pacotes entre máquinas.

Ele não é confiável, ele apenas entrega o pacote sem realizar nenhum tipo de verificação após a entrega.

Se quisermos confiabilidade podemos associar o protocolo IP ao protocolo TCP e se quisermos velocidade podemos associar o protocolo IP ao protocolo UDP.

IP + TCP = Confiabilidade IP + UDP = Velocidade

Estrutura do protocolo IP:

Analisando abaixo um caso específico, temos:

Version: Versão 4 (IPV4)
IHL: 5 (tamanho do header = 20 bytes) significa que usou 5 linhas, porque ele faz colunas x linhas
Type of service: (0) serve para uma melhoria do serviço
Total length: 64 (Tamanho total do pacote)
Identification: 0 (Não foi fragmentado e não precisou de uma identificação)

Flags: DF (Don't Fragment)
Fragment off set: 0 (A Flag não foi fragmentada, então aqui ficará 0)
Time to live: 64 (Serve para definir o SO, Sistema Operacional, 64 = Linux, 128 = Windows, 155 = unix) Esse valor pode ser alterado, porém esse é o padrão.
Protocol: TCP 6
Checksum: verificação do header
Source Address: IP remetente
Destination Address: IP destinatário

Fragmentação de Pacotes

Um frame ethernet aceita por padrão no máximo 1500 bytes, sendo assim, se o pacote tiver mais de 1500 bytes ele deverá em diversos pedaços, o que chamamos de fragmentação de pacotes.

Exemplo: O host cliente envia um ping para o host servidor com um pacote com 4000 bytes de tamanho.

Protocolo TCP

O protocolo TCP é um protocolo confiável para transmissão de dados pois ele garante a entrega das informações.

O TCP é orientado a conexão, isso significa que ele só transmite se garantir que uma conexão foi estabelecida om sucesso. (Three-way Handshake) O segmento TCP se comunica com portas.

Estrutura protocolo TCP

Source Port: A porta de origem é gerada automaticamente, random.
Destination Port: Porta de destino, do servidor, é uma porta fixa.
Sequence Number: Identifica que é
TCP Acknowledgment Number: Identifica qual o próximo numero da sequencia
Data Offset: (tamanho do header)
Reserved: Espaço reservado
Flags: URG, ACK, PSH, PST, SYN, FIN
Window: tamanho máximo do próximo segmento que ele aceita
Checksum: Verificação do header, payload..
Urgent Pointer: Prioridade para o conteúdo.

3WHS - Three-way Handshake

O TCP é orientado a conexão, isso significa que ele só transmite se garantir uma conexão foi estabelecida com sucesso.

Encerramento da conexão

Quando os hosts desejam encerrar a conexão nós veremos a flag FIN em ação.

Problema na conexão

O cliente enviou um SYN para estabelecer a conexão e o servidor retornou RST porque a porta não estava aberta, então retornou com problema na conexão.

PROTOCOLO UDP

O protocolo UDP assim cmo o TCP é um protocolo de transporte de dados, no entanto, não é confiável pois NÃO garante a entrega de dados.

O protocol UDP não é orientado a conexão, ou seja, não é necessário estabelecer uma conexão antes de começar a transmitir.

Sendo assim, ele entrega muito mais rápido e amplamente usado com streaming de vídeo, áudio... comunicações onde o foco é velocidade.

Protocolo HTTP

Funciona através de trocas de requisições entre cliente e servidor.

A estrutura é composta de HEADER e BODY.

O protocolo suporta vários métodos tais como GET, POST, HEAD, PUT, DELETE e OPTIONS

HTTP Request x HTTP Response O protocolo HTTP funciona com requisições, por exemplo, as de solicitações são chamadas de HTTP Request as de respostas são chamadas de HTTP Response.

Protocolo ICMP

O protocolo ICMP é um protocolo de alerta por mensagens, ele emite avisos sobre a situação da rede.

A estrutura básica do ICMP é simples, composta de tipos e códigos, cada um com sua função.## PING

O ping normalmente é utilizado para verificar a comunicação de rede entre hosts.

A resposta permite saber se a comunicação está ocorrendo, medir tempo de resposta e detectar problemas de lentidão.

Entendendo TTL

TTL ou tempo de vida do pacote IP serve justamente para que o pacote não fique vagando eternamente pela rede. Cada vez que o pacote IP passa por um roteador(hop) o seu TTL é decrementado (-1) até se tornar 0, quando o valor se torna 0 o roteador descarta o pacote.

O Windows usa TTL padrão 128 o Linux usa o TTEL padrão 64

O Unix usa o TTL padrão 255

TRACEROUTE com ICMP

Quando o TTL se torna 0 normalmente o roteador utiliza o protocolo ICMP para avisar, então ele utiliza o ICMP de tipo 11 e código 0.

Sendo assim, podemos manipulas o TTL afim de descobrir o caminho e a rota que o pacote percorre.

#ping com TTL para ir descobrindo a rota
ping -c 1 -t 1 www.businesscorp.com.br
ping -c 1 -t 2 www.businesscorp.com.br
ping -c 1 -t 3 www.businesscorp.com.br
.
.
.
#TRACEROUTE faz esse procedimento automaticamente. -n é para só trazer os IPS.
traceroute -n www.businesscorp.com.br
