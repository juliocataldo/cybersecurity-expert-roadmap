Labeling

#microsegmentation #network-security #offsec

Type: Cyber
Skills: Linux Micro-segmentation

A Label is a Key:Value pair, describing an attribute of assets. Labels allow you to categorize your assets by adding any metadata information.

Shared servers

servers that are part of multiple applications
Challenges:

  • Labeling
  • Servers with multiple values per key are not presented in a predictable way on the map
  • Policy
  • Servers that are used by multiple applications need to be part of multiple segments
  • Policy has to be reviewed by multiple applications owners

====================================================================

Assets

  • Labels are attached to Assets, objects that represent workloads
  • There are 3 types of assets: Managed and Unmanaged.

==Managed assets

  • Creation of managed assets:
  • Agent Installation
  • Orchestration (VMWares, AWS, Azure, kubernets)
  • Asset creation via API
  • Blue icon

==Unmanaged assets:

  • IP elements which are not associated with any managed asset, but that take part in traffic flows.
  • Displayed with gray icons
  • **Labels can be attached to both managed and unmanaged assets
  • Labels allow you to visualize the network in a common business language that your organization uses.

================

Using labels for visibility

Labels usage - Policy Creation

We can create rules with label using & (AND) or just selecting (OR) - The & option inform the asset need have the three labels to be part of this rule.

  • Labels are the preferred method for policy segmentation rules, rather than direct assets.
  • shorter, more readable rules
  • managing label members
  • Labels help manage assets:
  • in case of a breach, labels allow you to easily isolate the breached asset without impairing data center performance.

Labels Usage - RBAC configuration

Is possible to create a role and in the role defined the labels that is visible.

Project lifecycle

Explicit vc Dynamic label

Explicit:
In the Asset, you can create a label. Once associated, explicit labels are 'sticky'.
It is good to unmanaged asset.

Dynamic:
In the Labels page, you can create a new label with criteria (e.g. name is xxx, ip address in range 192.160.101.1-192.168.101.5). In the momento you install a new agent with this criteria, this agent will appear in the console with the label you created.

Labeling methods

  • REST API / CMDB Integration / SCM Playbook Integration
  • CLI
  • Automatic --> Label page
  • Orchestration
  • Manual --> Map or Assets page
  • Label Groups

Best practices

  1. Labeling scheme should have
  2. Use the only keys that are necessary to support your Business Goals
  3. Use only the values necessarily to support each defined key
  4. Define 'mandatory Key' and 'optional Key', so that global policies and uniform views may easily be implemented across the environment.
  5. Per asset, use only a single Valeu for each key.
  6. This will preserve consistent grouping of the Reveal map
  7. With multiple keys policy rules would be derived properly
