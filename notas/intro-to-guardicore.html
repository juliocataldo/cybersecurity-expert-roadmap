Label

Is the only simple way to build a segmentation policy. Label is a snippet of metadata that is attached to a workload and provides context about that workload. Labels are dynamic.

Micro-segmentation

Micro-segmentation is an emerging security best practice, which provides organizations with granular, workload-based security allowing for unparalleled visibility and control over communication flows within your environment.

With micro-segmentation, workload and process-level security controls are applied to data center and cloud assets to create secured, isolated zones, thus reducing the organizational attack surface and overall risk.

Architecture

The Centralized management server

can be deployed in any environment, as long as at least one Aggregator/Collector in the different environment is able to connect to it.

Agents

on instances/VMs automatically choose a working Aggregator in their appropriate environment/zone from which they receive control commands and to which they report collected data, and enforce segmentation policies

Aggregators

control registered Agents, collect data and forward it to the management server, and manage policy updates individual Agents

Components and their roles

  1. Components - Collectors - Reporting layer 4 network flow information to the Management. This data is used to gain wide visibility across the network, and visualize and alert on traffic with which Agents are not associated. This also allows IP Reputation analysis and detection of a network scanning activity.
  2. ESX Collector: For deception functionality, the ESX Collector is connected to a vSwitch promiscuos port.
  3. SPAN Collector: For deception functionality, a SPAN Collector should also be connect to a L2 Switch with a Trunk port.
  4. IP Flow Collector: The flow promotes security for devices without Agents.

  1. Components - Agents - Are deployed on guest systems and run 4 functional modules: Reveal, Enforcement, Deception and Detection
  2. Reveal: Collects process-aware network-flow events, including protocolos, ports and corresponding processes (path, user, command line, hash, etc), providing process-level visibility and file reputation
  3. Enforcement - enables the control over network flows - allowing/alerting/blocking flows.
  4. Deception - Captures and route failed traffic to deception servers. It is an alternative to deception functionality of a Collector
  5. Detection: Performs provides insight capabilities
  6. Components - Aggregators - Are points of communication and control for associated agents:
  7. Managing agent installation
  8. Receiving and aggregating agent data before sending on to the management layer
  9. Continuously deriving per-agent policy published by Management and populating it to Agents.

  1. Components - Management - Is the central component of each Centra installation
  2. Alerting and automated reporting
  3. Receiving, analyzing, enriching and managing storage of collected data
  4. Integration with siem
  5. monitoring and health control
  6. patching and upgrade
  7. etc
  8. Components - Deception - manages a farm of different-flavored honeypot instances
  9. Failed connections are redirected to a fully interactive honeypot instance, limiting the attackers interactions to that instance
  10. Following sessions recording and automatic analysis of its content, complete incident information is reported from the Deception Server to Management layer.
