Type: Cyber
Skills: Linux Micro-segmentation

Resource Utilization - CPU

==In most windows environment it is found to utilize less than 1% of CPU.
CPU limitations are applied using cgroups and/or ulimit mechanisms.

When installing agents for Linux without any explicit configuration settings, the Agents employs an auto logic for determinimg the optional package as follows..

==Low - less than 2 GBM is detected
Medium: between 2GB to 32GB is detected
Hard: more than 32Gb is detected

==All agent sub components initiation is done using a service named GC-AGENTS-SERVICE - In case of failure, the process is restarted after a 20 second wait time. The Kernel modules are loaded through WRAPPER bash scripts.

In case the kernel module is missing, the Agent will default to 'polling mode' where the events collection is done in user-space, and enforcement is not supported.

Installation Profile

export GC_profile=<profile>

Installation and Uninstalling Linux Agent

Installation:

  1. Download installation certificate from the aggregator
  2. Use the certificate to download and execute installation bash script from the aggregator. The aggregator supplies the bash script with parameters that ser which Agent modules should be turned on, according to the features activated on the aggregator.
  3. The script identifies the OD version and downloads the right installation package from the aggregator (RPM/DEB)
  4. The script sets the necessary environment variables for the installation of the Agent package and executes the installation.
  5. To run the script in verbose mode, first run: export GC_INSTALL_DEBUG=true

Uninstalling: 

gc-agent uninstall

KO Cloud

KO Cloud is a hosted environment that contains a storage bucket of all .ko objects of gc_enfocement kernel module for all supported Linux distributions for all existing and supported kernel versions in Akamai cloud

How Is KO Cloud Populated?

KO Fetching

AGENT --> Missing KO or KO does not match the kernel version --> ==gc-cert-client== requests a new KO from the aggregator AGGREGATOR --> The ==gc-guest-installer== service checks whether a matching KO exists in the cache ---> if no matching KO existe in the cache, ==gc-guest-installer== requests a new KO from the management server --> MANAGEMENT SERVER --> The ==components-nginx== service the requested LO, if it exists --> Every 60 minutes (configurable) ==ko-cloud-service== fetches new KOs from KO Cloud.

===============
==In case the matching ko file is not found on the management or on the KO Cloud - the agent will move to 'polling mode' and will provide a Reveal data.

Reveal Polling Mode

  • ==Pooling Mode== is based on netstat polling (L4 visibility)
  • If the Enforcement module is disabled or if there is a Missing KO, the agent will not report any reveal information
  • UI flags are raised in the Management so the issue can be detected by the administrator
  • In order for he Agent to repot Limited Reveal data (L4) the agent should have the Enforcemente module in Reveal Only.

|Module|Detecting short living connection|Detecting long living connection|
|---|---|---|
|Reveal in Polling mode|No|Yes|
|Enforcemente L4| Yes|Yes|

KO Cloud Safety

  • Feature is disabled by default
  • The KO no longer updates automatically - The user can choose whether to update the KO automatically.
  • The KO can be updated via Centra UI - similar to Temote Agent upgrade (RAU)
  • Timeout of 5 minutes
