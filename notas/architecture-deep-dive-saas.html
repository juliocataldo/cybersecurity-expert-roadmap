Aggregators and Collectors

Aggreators

The log file in Aggregators / Collectors is located at: /var/log/guardicore

==After Installation, the configuration file in Aggregators / Collectors is located at: /etc/guardicore/guardicore_setup.conf

Service Agg

  • gc-mitigation - backend for REVEAL MODULE of agents. This service fetches visibility reports from agents, perfomrs additional aggregation and forward the events to the management layer.
  • gc-enforcement - backend for ENFORCEMENTE module of agents. This service manages Segmentation policy updates to agents
  • gc-datapath - backend for Deception module of agents. This service is notified for redirection opportunities detected by agents
  • gc-detection-agents-server - backend for Detection module of agents. This service managers file integrity monitoring policy updates.
  • gc-controller-server - backend for Controller modules of agents. This service fetches healthcare status messages and manages agents conf updates
  • gc-guest-installer - the server that support agent "online installation" flow. In Linux, this service manages KI.

Services additional

  • gc-dc-inventory - This service holds a sync snapshot of all Label Group, Labels, Assets and asset IP. Whenever a change is detected, it triggers a policy recalculation and update for associated agents.
  • gc-network -db-sync: This service holds a synchronized snapshot of assigned VLANs, MACs, IPs and open ports to support redirection decisions.
  • telegraf - This service sends various applications performance metrics to the management
  • redis - Used internally for in-memory caching for other services
  • pull-config - synchronizes configuration from Management every 20 minutes, triggered by crontav

Collectors

Collectors main functionality is to Collect L4 visibility and redirect failed connections to Deception Server.
==All services are managed by a 'watchdog' service gc-monicore

  • Collectors integrate with the switching infrastructure, physical or virtual, and are used in cases when Agents cannot be deployed. Their roles:
  • Reporting layer 4 network flow to the management
  • Detect failed flows, forwarding those for deception investigation
  • Detecting network scanning activity
  • On physical infra, collectors connect to SPAN/TAP/Mirror ports or integrate with 3rd party Network Packet Brokers (NPB) solutions.
  • On VMware ESXi, Collectors use a promiscuous port group to receive a copy of all traffic traversing the selected vSwitch(es)
  • SPAN Collector - Should be also connected to a L2 Switch with a Trunk port
  • ESX Collector - Is connect to a vSwitch promiscuous port
  • IP Flow Collector
  • Flow Collector promotes security for devices without agents
  • Supports 3 protocols:
  • Netflow 5 and 9, IPFix and sFlow
  • Provides valuable information that is unavailable from other types of collector
  • The source of traffic is the netflow data
  • Single IP flow collector supports a max 7.5 million flows per second and up to 35 switches

Services Collectors

  • gc-mitigation - Detects L4 visibility flows, performs additional aggregation and forward the events to the management layer.
  • gc-datapath - This service detects failed connections, manages redirection decisions and if redirected tunnels the packets to the Deception Server Server and back.
  • gc-network -db-sync: This service holds a synchronized snapshot of assigned VLANs, MACs, IPs and open ports to support redirection decisions.
  • telegraf - This service sends various applications performance metrics to the management
  • redis - Used internally for in-memory caching for other services
  • pull-config - synchronizes configuration from Management every 20 minutes, triggered by crontab

Monitoring and Tshoot

  • Health Status (monicore-ctrl status)
  • UI - Components page
  • CLI alternative - monicore-ctrl status (use -v for verbose output)
  • Logs
  • Directory: /var/log/guardicore
  • Each service has a separate log
  • Past 8 log are compressed
  • Logs Verbosity
  • Permanent setting: edit /etc/guardicore/aggregator.conf and restart the service you want to move to verbose
  • Temp setting: gc-set-debug <service> [true|false]
  • List agents handled by an aggregator
  • gc-list-agents - List all agents module processed by the Agg and their respective uptime
  • map-workers - List Reveal processed by the Agg, adding OD, IP and Flags info
  • gc-list-enforcement-agents
  • gc-list-detection-agents
  • gc-list-controllers
  • Restarting services
  • UI - Select component --> Restart
  • CLI alternative: monicore-ctrl <action> <service-name>/all/*

  • Control components features
  • CLI: edit etc/guardicore/aggregator.conf and restart the services
  • Verify Cluster status by **executing the following commands on a quorum member
  • gc-cluster-info
  • gc-cluster-diagnostic
  • gc-list-roles
  • gc-network-db-dump
  • For out-of-sync Cluster components, attempt recovery with Kafka restart:
  • gc-cluster-kafka-restart
